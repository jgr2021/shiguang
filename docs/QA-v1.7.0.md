## 用户反馈的“读取状态超时”

已复现：从 Codex 桌面启动拾光时，工作目录里的同名 `codex.exe` 被旧版优先找到；它是桌面程序，不是 CLI。子进程退出后旧提示笼统显示为超时。源码从项目目录启动时不会触发，所以单独源码测试漏掉了这个问题。

修复：优先查找 Codex 自带 CLI 和原生 npm CLI；返回绝对路径；运行版本检查确认 `codex-cli` 身份；区分进程提前退出与具体接口真正超时。同一桌面启动环境下，修复后的打包诊断程序成功初始化、读取登录和7个模型。

最终桌面确认：已在安装到原位置的 v1.7 程序中直接点击“读取 Codex 状态”，成功显示登录、7个目录模型和可读取额度；聊天窗口也已显示真实的中文回复。

- 三语界面分别遍历14个连接选项和4个 Codex 快捷组合，检查 Enter/换行处理、IME 防误发分支、输入框伸缩、日程编辑确认，未出现界面回调错误。
- 断网测试通过待办增删改、冲突保护、草稿持久化、日记原文、待整理队列、重复归档、备份一致性、闰日日历、切换日期与关闭保存。

## 其他修复

- 待办提供给 AI 的索引增加时间和重要性，允许 AI 识别已有时段。
- 多日期附件的日期过滤匹配全部关联区间。
- API 连接检查不再把没有回答的空结构当作成功。
- 修改 API 地址清空尚未保存的 Key；检查期间换模型不会错误沿用旧检查结果。
- 等待 HTTP 响应头时可以迅速取消本机等待；服务商已收到的请求仍可能计费。
- 后台回调异常后继续处理后续事件；读取大文本时先限制读取字节数。
- 主界面只保留设置中的备份入口，Codex 状态读取合并，程序位置折叠，移除空白待办区的重复提示。

## 范围
