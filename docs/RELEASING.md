# 版本发布约定

每次交付新版本，都要同步 GitHub 源码、更新说明和可下载程序，保持本机版本与公开下载入口一致。

1. 更新程序版本、安装器版本、`CHANGELOG.md` 及该版说明；如有未完成的接入或验收，明确标注为预览。
2. 从源码构建，在独立目录使用 `packaging/prepare_release.py` 整理程序文件。不得打包个人数据目录；日记、附件原件、密钥、账号绑定、私有配置和自动任务均不应进入公开仓库或分发包。
3. 构建 Windows 安装包与免安装 ZIP，生成 `SHA256SUMS.txt`。
4. 检查待提交文件，提交并非强制推送源码。Release 标签必须指向对应构建的源码提交。
5. 先创建草稿 Release，上传安装包、ZIP 与校验值，核对上传大小及 GitHub 返回的摘要后再公开。未完成验收的版本使用 prerelease。
6. 同步 README、产品网站、三语入门文档的版本和下载链接；保留旧版文档和下载文件，旧截图注明版本。
7. 确认远端提交、公开 Release 及下载文件存在。网站部署未完成或发布失败时，说明具体状态，不声称已经更新。

构建成功不等于功能验收成功。仅在用户要求测试或验证时运行测试，分别记录实际覆盖范围。GitHub App 注册、私有仓库同步、AI 额度等未接通事项不能作为已可用功能宣传。
